# PackageGraph

Консольное приложение для анализа зависимостей пакетов.

Проект реализован на Java. Приложение позволяет считывать зависимости пакетов из файла тестового репозитория или из файла `Cargo.toml` в GitHub-репозитории.

## Возможности

- Чтение параметров из YAML-конфигурации.
- Проверка корректности параметров конфигурации.
- Получение прямых зависимостей из `Cargo.toml`.
- Чтение тестового графа зависимостей из файла.
- Поиск транзитивных зависимостей с помощью итеративного обхода в глубину (DFS).
- Поиск прямых и транзитивных обратных зависимостей в тестовом репозитории.
- Ограничение глубины анализа.
- Фильтрация пакетов по подстроке.
- Обнаружение циклических зависимостей.
- Выгрузка графа в PlantUML и PNG.

## Технологии

- Java 21
- Maven
- SnakeYAML 2.2
- JUnit 5

## Конфигурация

Настройки приложения находятся в файле `config.yaml`.

Пример конфигурации:

```yaml
packageName: A
repository: tests/test-repository.txt
testRepository: true
version: "1.0.0"
outputFile: dependency-graph.png
maxDepth: 10
filterSubstring: ""
```

Описание параметров:

| Параметр | Назначение |
|---|---|
| `packageName` | Имя пакета, для которого анализируются зависимости |
| `repository` | URL GitHub-репозитория или путь к тестовому файлу |
| `testRepository` | Режим работы: `true` — тестовый репозиторий, `false` — Cargo |
| `version` | Версия пакета |
| `outputFile` | Имя файла изображения графа |
| `maxDepth` | Максимальная глубина анализа |
| `filterSubstring` | Подстрока для исключения пакетов из анализа |

### Проверка ошибок конфигурации

В отдельной копии `config.yaml` подставь одно неправильное значение из
таблицы и передай путь к этой копии при запуске. Программа назовёт параметр
с ошибкой и завершится с кодом `1`.

| Параметр | Пример неправильного значения |
|---|---|
| `packageName` | `"A!"` |
| `repository` | `tests/missing.txt` при `testRepository: true` |
| `testRepository` | `"true"` в кавычках |
| `version` | `"oops"` |
| `outputFile` | `graph.jpg` |
| `maxDepth` | `-1` |
| `filterSubstring` | `false` без кавычек |

## Тестовый репозиторий

В тестовом режиме приложение использует текстовый файл, в котором каждая строка описывает пакет и его зависимости.

Пример:

```text
A: B, C
B: D
C: D
D: A
E:
```

## Запуск

Для запуска нужны JDK 21 и Maven. Из корня проекта:

```powershell
mvn compile
.\run.bat
.\run.bat tests/visualization/rand.yaml --visualize
```

В Linux и macOS те же параметры можно передать скрипту `./run.sh`.
При нестандартном пути к локальному кэшу Maven задай `MAVEN_REPO_LOCAL`.

В IntelliJ IDEA импортируй `pom.xml` и запусти класс `Main`.
Путь к YAML-файлу и флаг режима передаются через **Program arguments**.

## Обратные зависимости

В режиме `--reverse` приложение выводит пакеты, которые зависят от выбранного пакета.
Включи `testRepository: true` и передай `--reverse` в поле **Program arguments** конфигурации запуска класса `Main`.
Из терминала можно запустить тот же режим с настройками из `config.yaml`.

```powershell
.\run.bat --reverse
```

Для другого YAML-файла передай в **Program arguments** его путь перед флагом, например `demo.yaml --reverse`.

Примеры используют файл `tests/test-repository.txt`.

| `packageName` | `maxDepth` | `filterSubstring` | Результат |
|---|---:|---|---|
| `D` | 2 | `""` | `B`, `A`, `C` |
| `D` | 1 | `""` | `B`, `C` |
| `D` | 2 | `"B"` | `C`, `A` |
| `E` | 2 | `""` | Обратные зависимости отсутствуют |

## Визуализация

Передай `--visualize` в **Program arguments** конфигурации `Main`.
Чтобы выбрать отдельный YAML-файл, передай путь перед флагом. Пример для IntelliJ IDEA:

```text
tests/visualization/rand.yaml --visualize
```

Программа сохраняет PNG по пути `outputFile` и создаёт рядом одноимённый `.puml`.
Стрелка направлена от пакета к его зависимости. Ограничения `maxDepth` и
`filterSubstring` действуют и при визуализации. PNG рисуется средствами Java,
а текст PlantUML можно отдельно открыть в редакторе диаграмм.

Для реального GitHub-репозитория укажи `testRepository: false`. При визуализации
программа читает `Cargo.lock` с тега указанной версии и строит граф по
зафиксированным в нём связям. У тега должен быть доступен lock-файл.
Для локальной демонстрации задай `testRepository: true` и путь к файлу `.lock`
или к тестовому графу с буквенными именами.

### Три примера и сравнение с Cargo

Демонстрационный lock-файл воспроизводит связи из опубликованного примера
`cargo tree` в The Cargo Book. Для трёх выбранных пакетов проверены:

| Конфигурация | Прямые зависимости | Рёбер с учётом транзитивных |
|---|---|---:|
| `tests/visualization/rand.yaml` | `getrandom`, `libc`, `rand_chacha`, `rand_core` | 9 |
| `tests/visualization/getrandom.yaml` | `cfg-if`, `libc` | 2 |
| `tests/visualization/rand_chacha.yaml` | `ppv-lite86`, `rand_core` | 5 |

В выводе `cargo tree` общий пакет может повторяться с пометкой `(*)`, а на
диаграмме есть один узел пакета с несколькими входящими стрелками. У примеров
совпадают рёбра. Для других репозиториев результаты могут разойтись, если
Cargo скрывает зависимости для другой платформы или неактивных возможностей,
а анализатор отображает связи из lock-файла.
[Пример и параметры cargo tree](https://doc.rust-lang.org/cargo/commands/cargo-tree.html).

Файлы трёх примеров создаются в `target/diagrams`.

### Проверка на релизе ripgrep

Файл `tests/visualization/ripgrep-online.yaml` задаёт пакет `ripgrep` версии
`14.1.1`. Первая команда запрашивает манифест и выводит прямые зависимости.
Вторая читает lock-файл того же релиза и сохраняет граф с глубиной 2.

```powershell
.\run.bat tests/visualization/ripgrep-online.yaml
.\run.bat tests/visualization/ripgrep-online.yaml --visualize
```

На оригинальных файлах релиза проверены 13 прямых зависимостей. При глубине 2
граф содержит 34 узла и 47 рёбер.

Для отдельной проверки с установленным Cargo выполни из корня PackageGraph:

```powershell
git clone --depth 1 --branch 14.1.1 https://github.com/BurntSushi/ripgrep.git target/ripgrep-source
cargo tree --manifest-path target/ripgrep-source/Cargo.toml --locked `
  --package ripgrep@14.1.1 --target all --depth 2 --prefix depth --no-dedupe
```

Результаты сравнения на теге `14.1.1` (коммит `4649aa9`) при глубине 2:

| Источник | Уникальных узлов | Уникальных рёбер |
|---|---:|---:|
| PackageGraph, `target/diagrams/ripgrep.puml` | 34 | 47 |
| Cargo 1.100.0, `cargo tree` | 32 | 41 |

Сравнение выполнено по направленным парам «пакет с версией → зависимость с
версией». Все 41 ребро из Cargo присутствуют в графе PackageGraph. Ещё шесть
связей из lock-файла отсутствуют в дереве для выбранного запуска.

| Причина | Рёбра, которые показывает только PackageGraph |
|---|---|
| Опциональные зависимости без включённой возможности | `bstr → serde`, `grep → grep-pcre2` |
| Зависимости для разработки и тестирования вложенных пакетов | `grep → termcolor`, `grep → walkdir`, `ignore → bstr`, `ignore → crossbeam-channel` |

Ключ `--target all` включает зависимости для всех платформ. PackageGraph
отображает связи, записанные в `Cargo.lock`. Cargo строит дерево для выбранного
пакета и включённых возможностей, поэтому тестовые зависимости его
вложенных пакетов в этом выводе отсутствуют.

## Ограничения

- В режиме Cargo приложение ищет файлы в GitHub-репозитории по тегу `v<версия>` или `<версия>`.
- Для прямого анализа манифест должен задавать имя и версию явно в секции `[package]`.
- Выводятся ключи прямых зависимостей из обычных, сборочных, тестовых и платформенных секций манифеста.
- Учитываются объявления для всех платформ и опциональные зависимости.
  Cargo при сборке выбирает зависимости с учётом платформы и включённых возможностей (features).
