# PackageGraph

Консольное приложение для анализа зависимостей пакетов.

Проект реализован на Java. Приложение позволяет считывать зависимости пакетов из файла тестового репозитория или из файла `Cargo.toml` в GitHub-репозитории.

## Возможности

- Чтение параметров из YAML-конфигурации.
- Проверка корректности параметров конфигурации.
- Получение прямых зависимостей из `Cargo.toml`.
- Чтение тестового графа зависимостей из файла.
- Поиск транзитивных зависимостей с помощью итеративного обхода в глубину (DFS).
- Ограничение глубины анализа.
- Фильтрация пакетов по подстроке.
- Обнаружение циклических зависимостей.

## Технологии

- Java 21
- Maven
- SnakeYAML 2.2
- JUnit 5

## Конфигурация

Настройки приложения находятся в файле `config.yaml`.

Пример конфигурации:

```yaml
packageName: A
repository: tests/test-repository.txt
testRepository: true
version: "1.0.0"
outputFile: dependency-graph.png
maxDepth: 10
filterSubstring: ""
```

Описание параметров:

| Параметр | Назначение |
|---|---|
| `packageName` | Имя пакета, для которого анализируются зависимости |
| `repository` | URL GitHub-репозитория или путь к тестовому файлу |
| `testRepository` | Режим работы: `true` — тестовый репозиторий, `false` — Cargo |
| `version` | Версия пакета |
| `outputFile` | Имя файла изображения графа |
| `maxDepth` | Максимальная глубина анализа |
| `filterSubstring` | Подстрока для исключения пакетов из анализа |

## Тестовый репозиторий

В тестовом режиме приложение использует текстовый файл, в котором каждая строка описывает пакет и его зависимости.

Пример:

```text
A: B, C
B: D
C: D
D: A
E:
```

## Запуск

Для сборки проекта используется Maven.

В IntelliJ IDEA открой окно Maven и выбери:

`Lifecycle → compile`

Для запуска приложения выполни запуск класса `Main`.

## Запуск тестов

В окне Maven выбери:

`Lifecycle → test`

В проекте используются автоматические тесты JUnit 5.

## Ограничения

- В режиме Cargo приложение ищет `Cargo.toml` в GitHub-репозитории по тегу `v<версия>` или `<версия>`.
- Выводятся ключи прямых зависимостей из обычных, сборочных, тестовых и платформенных секций манифеста.
- Учитываются объявления для всех платформ и опциональные зависимости.
  Cargo при сборке выбирает зависимости с учётом платформы и включённых возможностей (features).
